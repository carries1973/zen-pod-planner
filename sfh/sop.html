Application-to-Lease SOP: Buildium

v2.0 · July 2026 · Owner: Leasing Administration · Applies to AB / BC / SK · Screening via SingleKey (Equifax)
How to read this document

This is the end-to-end path a leasing administrator follows to take a prospect from a submitted application to an active lease in Buildium. Follow the numbered stages top to bottom. Every stage tells you three things: what must be true before you proceed (Requirements), what to click (Actions), and exactly when to record a Note in Buildium so the file is audit-ready.

✓REQUIREMENTS
What must be complete/verified before you move on. Treat each box as a gate.
▶ACTIONS
The exact Buildium (or SingleKey) clicks for the stage.
✎LOG A NOTE
Record this in the applicant/lease Notes with your initials + date.
!DECISION GATE
A real approve/deny decision — pause and confirm before acting.
The pipeline at a glance
1Application Received
2Requirements Check
3Screening
4Approve / Deny
5Move In → Lease
6eLease + e-Sign
7Activate Lease
8Move-In / Onboard

Yellow = decision gate. Buildium native TransUnion screening is US-only, so Stage 3 uses SingleKey (Equifax Canada) tracked with Buildium custom fields.

1
Buildium · Leasing › Applicants

Application Received

A prospect submits a rental (or co-signer) application from your listing or public site. It lands on the Applicants dashboard.
✓Requirements to proceed
  • Applicant full legal name captured
  • Valid email address on the application (required for screening & e-sign)
  • Target property & unit selected
  • Application fee handled per ZEN policy
▶Actions
  1. Open Leasing › Applicants and click the applicant.
  2. Confirm contact info, employment, rental history, and any uploaded attachments are present.
  3. If you entered the application manually on the prospect's behalf, verify name + email are complete.
✎Log a note when…

…the application is received / logged. Record: source (Rentfaster, Rentals.ca, walk-in, etc.), date received, and any items still outstanding. — e.g. "App received 24-Jul via Rentfaster; missing pay stub, requested. — CS"

2
Buildium · Applicant record

Application Review & Requirements Check

Confirm the applicant meets ZEN's documented rental criteria before spending on a screen. Apply the same criteria to every applicant.
✓Requirements to proceed
  • Government-issued photo ID on file
  • Proof of income (pay stubs / offer letter / bank statements)
  • Income meets ZEN rent-to-income threshold [insert ZEN ratio, e.g. 3× rent]
  • Current + prior landlord references listed
  • Employment reference / contact listed
  • Consent-to-screen language acknowledged
▶Actions
  1. Cross-check each required document against the checklist above.
  2. If anything is missing, contact the applicant and pause here — do not screen an incomplete file.
  3. When complete, proceed to screening.
✎Log a note when…

…you finish the requirements check. Record: what was verified, what was missing/followed-up, and confirmation the file is complete and ready to screen. — "Reqs verified: ID ✓, 2 stubs ✓, income 3.2× ✓, 2 LL refs ✓. Ready to screen. — CS"

3
Buildium custom fields → SingleKey (Equifax)

Tenant Screening — SingleKey / Equifax

Buildium's native screen is US-only, so ZEN runs the screen in SingleKey and controls it with Buildium custom fields.
✓Requirements to proceed
  • Documented applicant consent (never order without it)
  • SingleKey account with ID verification complete
  • Payer decided (applicant-paid vs ZEN account) per policy
▶Actions
  1. In Buildium, set custom field Screening Action = "Initiate Screening".
  2. Set Screening Type = "SingleKey Equifax"; mark Consent on File = Y.
  3. In SingleKey: Tenant reports › Order new report.
  4. Choose Create invite (applicant enters details + consent) or Enter tenant info (key in name, DOB, address, SIN; upload consent + ID).
  5. Select the rental unit (must match the Buildium unit).
  6. At checkout choose Equifax (Canada), confirm payer, place order.
  7. Back in Buildium set Screening Action = "Screening In Progress" + Date Initiated.
✎Log a note when…

…the screen is ordered and again when the report returns. Record: bureau (Equifax), order date, payer, and on return the result summary + report location. — "Equifax ordered via SingleKey 24-Jul, applicant-paid. Report rec'd 24-Jul, score/flags summarized, PDF filed. — CS"

4
⚠ Decision Gate · Leasing › Applicants (status dropdown)

Approve or Deny

A real decision with consequences. Weigh the screening result against ZEN criteria, then set the applicant status. This is a natural point to move to Opus for the adjudication itself.
✓Requirements to proceed
  • Screening report reviewed in full
  • Decision consistent with ZEN criteria applied to all applicants
  • For a decline: adverse-action rationale documented
▶Actions
  1. Open the applicant. In the status dropdown (top-left of the applicant summary) choose Approved — or Defer / Cancel / Reject as needed.
  2. Buildium does not auto-notify the applicant. Send the acceptance (or adverse-action) notice manually per ZEN template.
✎Log a note when…

…the decision is made. Record: decision, who decided, the basis (tie to criteria/report), and the date the applicant was notified. Declines must capture the adverse-action reason. — "Approved 24-Jul on income + clean Equifax; acceptance notice sent 24-Jul. — CS/Approver"

5
Buildium · Applicants › Move in → Add Lease

Move In & Create the Lease

Convert the approved applicant into a lease. Their profile data carries over automatically.
✓Requirements to proceed
  • Applicant status = Approved
  • Lease terms confirmed (dates, rent, deposit, unit)
  • Decision made: executed lease (already signed) vs draft lease (collect e-signatures)
▶Actions
  1. Leasing › Applicants → open the approved applicant → click Move in.
  2. No existing lease → you land on Add Lease. (Existing lease on the unit → Add to lease instead.)
  3. Enter lease dates + type. Choose Record an executed lease (papers already signed) or Record a draft lease (eLeasing / e-signatures).
  4. Complete rent, deposit, and remaining details → Create lease.
✎Log a note when…

…the lease record is created. Record: lease type (executed/draft), term dates, rent, deposit, and any concessions. — "Draft lease created: 01-Aug-26→31-Jul-27, $1,850, DD $1,850, 1st-mo free? No. — CS"

6
Buildium · Leasing › Draft leases (eLease / Dropbox Sign)

Build the eLease & Send for e-Signature

Assemble the lease packet, place fields, and route it to signers. Skip to Stage 7 if you recorded an already-executed lease.
✓Requirements to proceed
  • Correct lease template / packet selected (only one template per lease)
  • All addenda included (pet, insurance, no-smoking, province-specific)
  • All signers added (tenant, co-signer, staff, owner) in the right order
  • Signature, initial, and merge fields placed for every signer
▶Actions
  1. From the draft lease, build/select the lease packet; confirm document order.
  2. Add signers and set signing order (Signer 1 → Signer 2 …). Avoid the "Me (now)" field.
  3. Place signature/initial fields and Buildium merge fields (names, dates, rent, address).
  4. Send the eLease to all signers in one click; track status per signer and follow up.
✎Log a note when…

…the eLease is sent, and on each follow-up. Record: date sent, who has signed, outstanding signers, and reminders sent. — "eLease sent 24-Jul to tenant + guarantor; tenant signed, guarantor pending, reminder 26-Jul. — CS"

7
Buildium · Draft lease → Activate

Activate the Lease

Once all signatures are in, activate the draft so it becomes a live lease on the rent roll. The signed eLease auto-syncs to the lease summary.
✓Requirements to proceed
  • All required signatures collected
  • Signed eLease saved to the lease record
  • Move-in charges/deposit set correctly
▶Actions
  1. Confirm every signer is complete.
  2. Activate the draft lease so it appears as an effective lease on the rent roll.
  3. Verify the signed eLease is attached to the lease summary page.
✎Log a note when…

…the lease is activated. Record: activation date, confirmation all signatures collected, and that the executed copy is filed. — "Lease activated 27-Jul; all sigs in; executed PDF on lease summary. — CS"

8
Buildium · Lease / Resident portal

Move-In & Onboarding

Collect first funds, set up the resident, and complete move-in.
✓Requirements to proceed
  • Security deposit + first month's rent received/scheduled
  • Tenant insurance confirmed (if required)
  • Resident Center invite sent & accepted
  • Move-in inspection scheduled; keys/fobs assigned
▶Actions
  1. Record/confirm deposit and first payment on the lease ledger.
  2. Send Resident Center setup + welcome communication.
  3. Complete the move-in condition inspection and hand over keys.
✎Log a note when…

…move-in is complete. Record: funds received, portal active, inspection done, keys issued, move-in date. — "Move-in 01-Aug complete: DD + 1st rent posted, portal active, inspection filed, 2 fobs issued. — CS"

Compliance & Notes Discipline (AB / BC / SK)

Consent first, always. Never order a credit/background report without documented consent (PIPEDA + provincial privacy law). Apply screening criteria identically to every applicant to avoid human-rights exposure. For any decline, follow ZEN's adverse-action process and retain the consent + report per ZEN retention policy. Do not store SIN or ID images outside approved systems.

The one-line notes rule. Every note = what happened + basis/detail + your initials + date. If it isn't noted, it didn't happen. Notes are logged at every ✎ marker above so any teammate can pick up the file and know exactly where it stands and why each decision was made.
